# Pinctrl: Silicon Labs Series 2 (DBUS)

When to read this: you are assigning or moving pins on a Silicon Labs EFR32/EFM32 Series 2 part (xG21 through xG29, or an MGM/BGM module). Read references/pinctrl/model.md first for the common pinctrl model; this page adds the Silabs-specific paths, macro format, group conventions, and the timer/PWM quirk.

## Identification

The authoritative silicon selector is the first `/`-segment of `cmake.board.qualifiers` in `<build-dir>/build_info.yml` (requires Zephyr 4.0 or newer). On Silabs boards the qualifier is the full SoC part number, so match on its prefix:

```shell
grep -n 'qualifiers' <build-dir>/build_info.yml
# qualifiers: efr32mg24b210f1536im48   (prefix efr32 -> Silicon Labs)
```

- SoC prefixes: `efr32`, `efm32`, `mgm`, `bgm`.
- Board-name patterns (pre-build fallback only): radio boards `xg2*`, `slwrb*`; dev and starter kits `sltb*`, `slstk*`, `pg2*`; public short names `bg2*`, `mg2*`, `fg2*`, `sg2*`, `zg2*`.
- Scope of this page: Series 2 only (xG21 through xG29: MG/BG/FG/SG/ZG/PG parts, plus the MGM/BGM radio modules). Series 1 and the SiWx91x/SiM3 families use different encodings: see Out of scope.

## Where pin data lives

Series 2 routes digital signals through the DBUS scheme. The pin data ships inside the Zephyr repo itself (not in a HAL module directory):

- Per-family generated header (the one you `#include` and grep): `$ZEPHYR_BASE/include/zephyr/dt-bindings/pinctrl/silabs/<family>-pinctrl.h`, for example `silabs/xg24-pinctrl.h`. Generated by `gen_pinctrl.py` in the `hal_silabs` module.
- Shared packing macros: `$ZEPHYR_BASE/include/zephyr/dt-bindings/pinctrl/silabs-pinctrl-dbus.h` (defines `SILABS_DBUS` and the bit layout; you never include this directly, the family header pulls it in).
- Working examples to imitate: the board's shipped pinctrl dtsi, for example `$ZEPHYR_BASE/boards/silabs/radio_boards/xg24/xg24_rb418xc-pinctrl.dtsi`.

Gap-fill: the family stem is `xg<NN>` where NN is the two-digit series number in the part number (`efr32mg24...` maps to `xg24-pinctrl.h`; MGM240 modules are xG24-based). Confirm against the user's checkout:

```shell
ls "$ZEPHYR_BASE/include/zephyr/dt-bindings/pinctrl/silabs/"
```

The family header is a flat list of `#define`s in two levels:

```c
/* Level 1, intermediate: one per (peripheral, signal). It pins down the
 * routing constants and leaves only port and pin free. */
#define SILABS_DBUS_EUSART1_TX(port, pin)  SILABS_DBUS(port, pin, 29, 1, 4, 6)

/* Level 2, per-pad: one per pad that signal can route to. THIS is the
 * symbol you write in the devicetree. */
#define EUSART1_TX_PC1  SILABS_DBUS_EUSART1_TX(0x2, 0x1)

/* Fixed-function pads (debug, SWV, trace) skip the intermediate level. */
#define GPIO_SWV_PA3    SILABS_FIXED_ROUTE(0x0, 0x3, 1, 0)
```

Per-pad symbols follow `<PERIPHERAL>_<SIGNAL>_P<PORT><PIN>` (ports A to K): `EUSART1_TX_PC1`, `USART0_RTS_PA5`, `TIMER1_CDTI2_PB2`. To enumerate every pad a signal can reach:

```shell
grep -n '#define EUSART1_TX_' "$ZEPHYR_BASE/include/zephyr/dt-bindings/pinctrl/silabs/<family>-pinctrl.h"
```

## Authoring format and macro

Style: group (see references/pinctrl/model.md). The peripheral's `pinctrl-N` references a group node you write under `&pinctrl`; the group's `groupN` children carry the pin cells.

- The cell property is `pins`, NOT `pinmux`. This is the key structural difference from the NXP and ESP32 group styles.
- Group label convention: `<peripheral>_default` (no `pinmux_` prefix), for example `eusart1_default`, `i2c0_default`, `timer0_default`.
- Default child name: `group0`; add `group1`, `group2`, ... when different signals need different electrical properties.
- Each cell is a pre-defined macro symbol, written as a cell value, never as a phandle, and multi-cell lists keep their commas:

```dts
group0 { pins = <EUSART1_TX_PC1>, <EUSART1_SCLK_PC3>; };  /* correct */
group0 { pins = <&EUSART1_TX_PC1>; };                     /* WRONG: a macro is not a label */
group0 { pins = <EUSART1_TX_PC1 EUSART1_SCLK_PC3>; };     /* WRONG: reads as one tuple */
```

The preprocessor compiles each macro to one packed 32-bit integer with this DBUS layout:

| Field | Shift | Mask |
| --- | --- | --- |
| PORT (0 = A, 1 = B, ...) | 0 | `0x0000000F` |
| PIN | 4 | `0x000000F0` |
| PERIPH_BASE | 8 | `0x0003FF00` |
| HAVE_EN | 18 | `0x00040000` |
| EN_BIT | 19 | `0x00F80000` |
| ROUTE | 24 | `0x1F000000` |
| HAVE_ROUTE | 29 | `0x20000000` |

`SILABS_FIXED_ROUTE` sets HAVE_EN to 1 and HAVE_ROUTE to 0. Verified reference values: `EUSART1_TX_PC1` compiles to `0x26241d12`, `GPIO_SWV_PA3` to `0x40130`.

You never compute these by hand when authoring: write the symbol. The layout matters when reading a built tree, because after the build only the integer remains in `build/zephyr/zephyr.dts`:

```shell
grep -n 'pins = <' <build-dir>/zephyr/zephyr.dts
# decode which pad a packed value routes: port letter, then pin number
python3 -c "v = 0x26241d12; print('P' + chr(ord('A') + (v & 0xF)) + str((v >> 4) & 0xF))"
# -> PC1
```

Consequence for drift checks: never string-compare an overlay's `<EUSART1_TX_PC1>` against `zephyr.dts` (see references/debugging.md).

## Node shape example

Complete shape, matching the shipped xG24 radio-board dtsi: the group definition under `&pinctrl`, then the peripheral referencing it.

```dts
#include <zephyr/dt-bindings/pinctrl/silabs/xg24-pinctrl.h>

&pinctrl {
    eusart1_default: eusart1_default {
        group0 {
            pins = <EUSART1_TX_PC1>, <EUSART1_SCLK_PC3>;
            drive-push-pull;
            output-high;
        };
        group1 {
            pins = <EUSART1_RX_PC2>;
            input-enable;
            silabs,input-filter;
        };
    };

    i2c0_default: i2c0_default {
        group0 {
            pins = <I2C0_SCL_PC5>, <I2C0_SDA_PC7>;
            drive-open-drain;
            bias-pull-up;
        };
    };
};

&eusart1 {
    pinctrl-0 = <&eusart1_default>;
    pinctrl-names = "default";
    status = "okay";
};
```

Open the pin controller by its label `&pinctrl` (never by path). `pinctrl-0` and `pinctrl-names` are a positional pair; never write one without the other.

## Required includes

Every overlay whose `pins` cells use macro symbols must include the per-family header at the top of the file:

```dts
#include <zephyr/dt-bindings/pinctrl/silabs/<family>-pinctrl.h>
```

Without it the build fails on the unexpanded symbol. Place the `#include` before any node blocks; see references/overlay-authoring.md for include-merging rules and overlay file placement.

## Defaults and per-peripheral conventions

Silabs convention splits groups by electrical role. Driven (output) signals share one push-pull group; the RX input sits alone with the glitch filter enabled.

| Peripheral (label prefix) | Group layout |
| --- | --- |
| `eusart`, `usart` (async serial and SPI-style synchronous mode) | `group0`: driven signals (TX, CLK/SCLK, CTS, RTS, CS) with `drive-push-pull; output-high;`. `group1`: RX alone with `input-enable; silabs,input-filter;` |
| `i2c` | one `group0`: SCL and SDA together with `drive-open-drain; bias-pull-up;` |
| `timer`, `letimer` (PWM outputs) | one `group0`: all outputs with `drive-push-pull; output-low;` |

- `silabs,input-filter` is the vendor-specific glitch filter for input signals; pair it with `input-enable`.
- For a fresh output-style group with no closer convention, start from `drive-push-pull; output-high;`.
- TIMER exposes signals `CC0` to `CC3` plus `CDTI0` to `CDTI2`; LETIMER exposes `OUT0` and `OUT1`.
- Pin-set requirements are the cross-vendor family rules (I2C needs SCL and SDA as a pair; the UART rules apply to `usart` and `eusart` labels): see the table in references/pinctrl/model.md.

## Quirks

### Timer and LETIMER: pinctrl lives on the pwm child

The `silabs,series2-timer` and `silabs,series2-letimer` wrapper nodes carry no `pinctrl-N` at all. Pinctrl lives on their PWM child node (`silabs,timer-pwm` / `silabs,letimer-pwm`, whose bindings include `pinctrl-device.yaml`). Two rules follow:

1. The pin group node keeps the wrapper's name: `timer0_default`, never `pwm_default`.
2. The `pinctrl-0` reference is written on the `pwm` child, not on `&timer0` itself. The wrapper also has a `counter` sibling child; only the `pwm` child takes pinctrl.

### Worked example: PWM output on TIMER0 (xG24)

Goal: drive a PWM signal from TIMER0 channel CC0 on an xG24 radio board. Overlay file: `<app>/boards/<board>.overlay` (placement rules in references/overlay-authoring.md).

```dts
#include <zephyr/dt-bindings/pinctrl/silabs/xg24-pinctrl.h>

&pinctrl {
    /* Group named after the WRAPPER (timer0), per convention. */
    timer0_default: timer0_default {
        group0 {
            pins = <TIMER0_CC0_PA6>;
            drive-push-pull;
            output-low;
        };
    };
};

&timer0 {
    status = "okay";

    /* Unlabelled child shipped by the SoC dtsi: open it by name.
     * pinctrl-0 goes HERE, not on the wrapper. */
    pwm {
        pinctrl-0 = <&timer0_default>;
        pinctrl-names = "default";
        status = "okay";
    };
};
```

Set `status = "okay"` on both the wrapper and the `pwm` child: a disabled parent makes the child unusable. Gap-fill: `TIMER0_CC0_PA6` follows the verified symbol pattern, but confirm that exact pad exists in your family header before building:

```shell
grep -n '#define TIMER0_CC0_' "$ZEPHYR_BASE/include/zephyr/dt-bindings/pinctrl/silabs/xg24-pinctrl.h"
```

Devicetree alone does not enable the subsystem: add `CONFIG_PWM=y` to `prj.conf`. Gap-fill: to consume the channel from C, add a label to the child in the overlay (`timer0_pwm: pwm { ... }`) and use `PWM_DT_SPEC_GET`; see references/dt-from-c.md.

### Other quirks

- The UART family goes by `usart` and `eusart` labels on Silabs; there is no `uart`-labelled node. USART/EUSART also provide SPI-style synchronous mode, which is why CLK/SCLK and CS appear in the serial group layout.
- The board qualifier is the full SoC part number (`efr32mg24b210f1536im48`), much longer than other vendors' qualifiers; match on the prefix only.
- Fixed-function pads (debug, SWV, trace) appear in the family header via `SILABS_FIXED_ROUTE`; they are valid `pins` cells like any other symbol.
- Multiple family headers share basenames with other vendors' `*-pinctrl.h`; the Silabs ones are recognizable by the `silabs/` path segment.

## Out of scope

Named explicitly so nothing gets guessed:

- Series 1 / Gecko parts (`GECKO_PSEL` macro format): a different encoding, not covered here.
- SiWx91x (siwx91x) and SiM3 (si32) families: separate pinctrl formats entirely.
- Analog bus allocation (`ABUS_*` entries in the same headers): a different bit-31-set encoding for analog routing, not routable digital pads; do not treat them as `pins` candidates for digital signals.

For any of these, fall back to imitating the board's shipped `-pinctrl.dtsi` (recipe in references/pinctrl/model.md).
